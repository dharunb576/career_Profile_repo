## NASA Web Server Log Analysis — Big Data Analytics Pipeline

**Project Type:** Big Data Analytics / Data Engineering  
**Status:** Core data-processing pipeline completed; dashboard visualization planned  
**Role:** Project Developer  
**Primary Technologies:** Python, PySpark, Apache Spark, Java 21, Pandas, PyArrow, Parquet, CSV

### Project Overview

Developed a big-data processing and web-server log analytics pipeline to process approximately **1.57 million NASA HTTP access log entries**. The project transforms raw server logs into structured datasets and generates analytical reports to help understand web traffic patterns, HTTP response statuses, frequently accessed URLs, client activity, and request trends.

The pipeline uses Python and PySpark to parse, transform, analyze, and export large volumes of log data into Parquet and CSV formats. The resulting datasets are prepared for further exploration through command-line reporting tools and business intelligence platforms such as Microsoft Power BI.

### Objectives

- Process large volumes of raw HTTP access logs efficiently using distributed data-processing concepts.
- Transform unstructured log entries into structured, analysis-ready datasets.
- Analyze web traffic patterns, HTTP methods, response statuses, and request activity.
- Identify frequently accessed URLs and hosts and summarize error responses.
- Export processed data into reusable formats for downstream analytics and visualization.

### Key Features and Implemented Functionality

- **Large-Scale Log Processing:** Processed approximately 1,569,898 NASA HTTP requests using PySpark.
- **Log Parsing and Transformation:** Implemented a structured pipeline to parse raw access logs and prepare records for analysis.
- **Data Processing with Spark:** Used Apache Spark through PySpark to perform data transformations and analytical operations.
- **Parquet Data Export:** Exported the processed dataset to `output/nasa_logs.parquet` for structured storage and subsequent analysis.
- **HTTP Status Code Analysis:** Generated summaries of HTTP response statuses to understand request outcomes.
- **Top URL Analysis:** Identified the most frequently accessed URLs.
- **Host Analysis:** Generated rankings of hosts based on request activity.
- **HTTP Method Analysis:** Summarized request methods used in the access logs.
- **Traffic Trend Analysis:** Generated hourly and daily traffic summaries.
- **Error Analysis:** Produced analytical reports related to HTTP errors.
- **CSV Report Generation:** Exported individual analytical results into CSV files for reporting and further exploration.
- **BI-Ready Data Preparation:** Prepared structured datasets suitable for downstream analysis in tools such as Microsoft Power BI.

### Technical Architecture

**Processing pipeline:**

Raw NASA Access Logs → Python Log Parser → PySpark Processing and Analysis → Parquet Dataset + CSV Analytical Reports → Future Dashboard Visualization

### Technology Stack

- **Programming Language:** Python
- **Big Data Processing:** PySpark, Apache Spark
- **Data Formats:** Parquet, CSV
- **Data Processing Libraries:** Pandas, PyArrow
- **Runtime Environment:** Java 21
- **Development Tools:** uv
- **Planned Visualization:** Microsoft Power BI and terminal-based dashboards

### Key Project Outcomes

- Processed approximately 1.57 million HTTP access log records.
- Created a repeatable pipeline for parsing, transforming, and analyzing web-server logs.
- Generated separate analytical datasets for HTTP statuses, top URLs, top hosts, request methods, hourly traffic, daily traffic, and errors.
- Produced reusable Parquet and CSV outputs for downstream reporting and visualization.

## AI Fake Photo Detector — Real vs. AI-Generated Image Classification

**Project Type:** Machine Learning / Computer Vision  
**Role:** Project Developer  
**Primary Language:** R  
**Dataset:** CIFAKE — 6,000 images (3,000 real and 3,000 fake)  
**Repository:** Fake_AI_Image_analyser  
**Status:** Model experimentation and evaluation; CNN feature-extraction approach explored

### Project Overview

Developed an image-classification project in R to distinguish real images from AI-generated fake images using the CIFAKE dataset. The project focuses on preparing image datasets, extracting numerical features, training machine learning models, and evaluating their ability to classify real and fake images.

Experimented with multiple classification approaches and recorded improvements in test accuracy through model development and evaluation. Also explored CNN-based feature extraction using MobileNetV2 as an alternative to conventional machine learning approaches.

### Objectives

- Prepare a balanced dataset of real and AI-generated images.
- Organize training and testing images to support model evaluation.

- Train and evaluate image-classification models.
- Compare experimental results and identify opportunities to improve classification accuracy.

### Dataset Preparation

- Prepared a dataset containing up to 6,000 images, with separate training and testing groups.
- Used a reproducible random seed during image selection.
- Organized image files using real/fake labels and training/testing identifiers.

## AgriVision — AI-Driven Smart Agriculture and Farm-Zone Visualization

**Project Type:** Smart Agriculture / Geospatial Application / AI Integration  
**Role:** Project Contributor and Developer  
**Primary Language:** Python  
**Repository:** `shyamsanjayg-agrivision-smart-farming`  
**Status:** Existing application enhanced; intelligent crop-suitability zoning remains a development goal.

### Project Overview

AgriVision is a smart agriculture application designed to help users visualize agricultural land and organize farm plots into crop-labelled zones. The application accepts GeoJSON farm boundaries, displays the selected land on an interactive map, and divides the plot into predefined zones for visualization. It also provides an AI-powered agricultural chatbot and an optional weather dashboard through external API integration.

The broader project objective is to develop a system that can help farmers identify suitable crop-growing areas within a selected landscape. The current implementation provides a foundation for geospatial visualization and agricultural assistance, with data-driven crop suitability analysis identified as a future enhancement.

### Key Features

- **GeoJSON Farm Plot Upload:** Accepts GeoJSON input representing a selected agricultural landscape.
- **Geospatial Visualization:** Displays farm boundaries and map information using Folium and Streamlit integration.
- **Farm-Zone Visualization:** Divides the selected plot into up to six predefined rectangular zones with crop labels and interactive tooltips.
- **Configurable Map Display:** Supports configurable zone counts, labels, map zoom, and map tile styles.
- **AI Agricultural Chatbot:** Provides a conversational agricultural assistance interface using the Groq API and LLaMA 3.3 70B Versatile model.
- **Weather Information:** Integrates with the Agromonitoring API to retrieve weather information when the required configuration is available.
- **Interactive Web Interface:** Uses Streamlit with custom HTML/CSS elements to present the application features.
- **Map Visualization:** Uses OpenStreetMap/CartoDB map tiles through Folium.

### Technology Stack

- **Programming Language:** Python
- **Application Framework:** Streamlit
- **AI Integration:** Groq API, LLaMA 3.3 70B Versatile
- **Geospatial Data:** GeoJSON, JSON
- **Interactive Mapping:** Folium, streamlit-folium
- **External API Integration:** Agromonitoring API, requests
- **Frontend Customization:** HTML, CSS
- **Map Data and Tiles:** OpenStreetMap, CartoDB
- **Configuration:** Streamlit Secrets
- **Development Environment:** Dev Containers

### Project Objectives

- Make agricultural land easier to visualize through interactive digital maps.
- Provide a foundation for dividing farm plots into organized crop-labelled zones.
- Integrate conversational AI to support agricultural information access.
- Connect external weather services to provide relevant environmental information.
- Establish a foundation for future data-driven crop-suitability recommendations.

### Current Limitations and Future Enhancements

- Replace predefined crop-zone labels with crop recommendations based on verified agricultural and environmental data.
- Improve polygon subdivision so zones remain accurately within irregular farm boundaries.
- Incorporate soil properties, rainfall, temperature, terrain, and crop requirements into a crop-suitability model.
- Add evidence-based crop suitability scoring and explainable recommendations.
- Improve validation of GeoJSON input and handling of invalid or unsupported geometries.
